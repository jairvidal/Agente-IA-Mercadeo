# infra/

Operational artifacts that run on the EC2 staging host. `terraform/` provisions the
cloud resources; the files in this directory live inside the host as the workload.

## Layout

| Path | Deploy target on EC2 | Purpose |
|---|---|---|
| `docker-compose.yml` | `/opt/sidoc-ai/docker-compose.yml` | 5-service stack: `caddy`, `backend`, `mcp-server`, `postgres` (pgvector pg17), `redis` |
| `Caddyfile` | `/opt/sidoc-ai/Caddyfile` | Reverse proxy + auto TLS via Let's Encrypt for `api.marketing.stg.sidocsa.com` |
| `postgres/init.sql` | `/opt/sidoc-ai/postgres/init.sql` | One-shot extension setup (`CREATE EXTENSION vector`) |
| `redis/redis.conf` | `/opt/sidoc-ai/redis/redis.conf` | AOF + LRU eviction config |
| `terraform/` | (n/a — runs from operator workstation or CI) | IaC for AWS resources |

## How env vars reach the containers

The runtime config lives in **AWS Secrets Manager** at `/sidoc-ai-marketing/{env}/runtime`
as a single JSON blob. On EC2 boot, `sidoc-ai-bootstrap.service` runs `bootstrap.sh` which:

1. `aws secretsmanager get-secret-value` reads the blob
2. `jq` flattens it to `KEY=VALUE` lines and writes `/run/sidoc-ai/.env` (tmpfs, mode `0600`)
3. `docker compose up -d` reads `/run/sidoc-ai/.env` as the docker-compose env file
4. Each service in `docker-compose.yml` declares `env_file: /run/sidoc-ai/.env` to receive the vars

No `.env*` lives on disk. The tmpfs file disappears on reboot and is regenerated by the service.

## Deploy mechanism

The files in this directory are **not** rsynced or built into a container image — they
are uploaded as-is to `/opt/sidoc-ai/` by the deploy workflow in E-00.5 (`deploy-staging.yml`):

1. GitHub Actions assumes the deploy role via OIDC
2. `aws ssm send-command` copies these files to the EC2 (or syncs via S3)
3. `docker compose pull && docker compose up -d`
4. `bootstrap.sh` reads SM into `/run/sidoc-ai/.env` and restarts containers

For manual changes during development, use `aws ssm start-session` and edit the files
on the host. Persist any change back to this repo to keep them in sync.
